# SIGNAL ARENA

## О проекте

**Signal Arena** — обучающая игра о навыках анализа и торговли на криптовалютных биржах, в которой сложный теоретический материал подаётся через игровой опыт, соревнование и визуальный язык арены.

В репозитории представлено большое количество материалов — прототипы, референсы,
эскизы, арт-ассеты, документы и реализации. **Большая часть этого материала представлена
на уровне концепции и не была утверждена как обязательная к исполнению.**

Ни один из файлов, папок или описаний в данном репозитории не является автоматически
обязательным к реализации. Концептуальные материалы служат источником идей и вдохновения,
а не инструкцией к действию.

Это — единственный источник правды о том, что должно быть реализовано. Всё, что не
явно указано в разделе «Утверждённые требования», считается концептуальным и не является
обязательным.

---

## Утверждённые требования

Это — обязательные условия, из которых состоит финальный продукт. Всё, что не указано
здесь, пока не является обязательным.

1. **Бэкенд с CRM-интерфейсом** для управления — реализуется в репозитории `backend/`
   (Fastify + SQLite/SQL.js + Drizzle + Zod + WebSocket, ~36 роутов `/api/v1`,
   AI-пайплайн для анализа и обработки данных).

2. **Фронтенд — игровой клиент** на фреймворке **Phaser 4** — реализуется в репозитории
   `phaser/` (TypeScript + Vite, сцены для вертикального цикла + обратной связи,
   механики (см. CONCEPT_IDEAS.md), прогрессия через освоение материала
   (костыли снимаются по мереду, а не «меняется эпоха»),
   а не меняет «эпоху»), детерминированный движок).

3. **Общий стиль тона текста** утверждён и обязателен для всех текстов игры.
   Описание — в файле `стиль_тон.txt`. Кратко: **«панк-таблоидная криптосатира»** —
   мрачная, драматичная, сухая подача крипторынка как абсурдной цивилизации.
   Формула хорошей фразы:
   `[Драматичный заголовок] + [простая правда] + [неприятный или смешной вывод]`.
   Подробные правила и примеры — в `стиль_тон.txt`.

## Планируется, но не обязательно в финальном релизе

Следующие элементы планируются, но **в самом начале даже в финальной версии релиза
игры может не присутствовать**. Они будут добавлены позже.

- **Токен игры и GameFi 2.0** — всё, что касается игрового токена, блокчейна, NFT и
  монетизации через игру в будущем.
- **Локализация интерфейса** под разные языки.
- **Настраиваемый стиль интерфейса** (цвета, темы, компоновка) — в будущем всё это будет
  представлено в виде товаров в **маркетплейсе**. Маркетплейс — основной будущий
  источник прибыли проекта.
- **Контент** (тексты обучения, рендеры сущностей врагов) — универсальные, не
  привязаны к конкретной эпохе или стилю.

> Всё, что не перечислено в «Утверждённые требования», считается концептуальным,
> включая фирменный стиль, арт-ассеты, референсы и эскизы.

## Директории

### `backend/`

Бэкенд проекта с интерфейсом управления в виде CRM.

- **Fastify** + **SQLite** (через `sql.js`) + **Drizzle ORM** + **Zod** + **WebSocket**
- ~36 роутов `/api/v1`
- AI-пайплайн для анализа и обработки данных
- Запуск: `cd backend && npm i && npm run start` (порт 8080)
- Модуль `aibackend`: движок, контент, API

### `phaser/`

Игровой клиент на **Phaser 4** + TypeScript + Vite.

- Сцены для вертикального цикла + обратной связи
- Механики: см. `CONCEPT_IDEAS.md`
- Прогрессия через освоение (костыли снимаются по мере усвоения, не смена «эпох»)
- Детерминированный движок
- Запуск: `cd phaser && npm i && npm run dev` (порт 3000)
- Стартовые скрипты, тесты (vitest), исходники в `src/`
- Документация: `ART_SPEC.md`, `USERFLOW.md`, `THIRD_PARTY_ASSETS.md`, `README_PHASER.md`

### `game_characters/`

Концептуальные арт-ассеты персонажей и врагов.

- Рендеры сущностей врагов (киты, медведи, фантомы, гоблины и т.п.)
- Примеры на уровне идеи: вид оформления, стиль иллюстраций
- Концептуальные материалы — не утверждены как обязательные к исполнению

**Разделение персонажа и фона.** Сам персонаж существует **отдельно от фона**:
персонаж — статичный (оживлять до уровня анимации движения избыточно), а его
проявление на фоне — анимированно. Это позволяет в будущем ставить **любого
персонажа на любой фон**, как по отдельности, так и вместе.

**Уровни силы и версии.** Аналогично играм с системой прогрессии, у любой сущности
есть **уровень силы — условно 1–99**. Количество визуальных версий для каждого уровня
будет разным: не для всех уровней нужна своя версия, а для некоторых — несколько.
На рисунке можно увидеть пример: как один и тот же персонаж (например,
*Leverage Goblin*) может выглядеть на разных уровнях.

**Форматы изображений.** Каждая сущность в конечном виде будет представлена в
нескольких форматах изображений:

| Формат | Где используется |
|---|---|
| Круглая аватарка с лицом | Инвентарь, профиль игрока, миниатюры в списках |
| Отдельный фон | Сцены боя, карточки сущностей |
| Самостоятельный персонаж (фигурка) | Боевая арена, анимации, рекламные материалы |

Каждая версия персонажа **выбирается заранее** (на этапе утверждения дизайна), чтобы
её можно было показать во всех форматах — и в самой игре, и в рекламных материалах,
и в будущих комбинациях персонажей.

**Имена сущностей.** Имена на всех языках остаются **на английском** языке
(термины из индустрии: *Leverage Goblin*, *FOMO Wraith*, *Paper Hands Poltergeist* и др.).
Остальной текст интерфейса локализуется. На русском языке игрок видит, например,
«Leverage Goblin 5lvl», а далее текст уже на русском. Имена не переводятся, чтобы
избежать качественно плохих локализаций — оставить термин на английском гораздо лучше,
чем кривой перевод.

**Помощник — `concept_B_arhivarius.png`.** Это **не враг**, а отдельный персонаж —
помощник в виде **скрепки** (отсылка к Microsoft Word). Один внешний вид — выбирать
не нужно. Персонаж выглядит и как скрепка, и как **мудрый старик** (форма бороды),
как у Йоды в *Звёздах*. Важно сохранить именно такой образ — он таит смысл.

- Персонаж используется **только в виде аватарки** — для сообщений и как **иконка
  помощи** в интерфейсе. Показывать его телом необязательно.
- Иконка налагается на любой фон так же, как и другие сущности.
- **Счётчик уведомлений** на иконке растёт по мере прогресса. По нажатию — дополнительная
  информация и помощь, раскрывающиеся по мере сложности.
- **Смысл персонажа** должен сохраняться: это **«старая аналоговая скрепка на пенсии»**,
  а не современный ИИ-ассистент. Диалоги намекают на прошлое («я пришёл из прошлого,
  чтобы помочь тебе в будущем»), но **не раскрывают образ полностью в лоб** — игрок
  должен считывать или постепенно раскрывать его суть.

### `brand_identity_main_idea/`

Фирменный стиль проекта **ещё не придуман** — логотип и окончательные визуальные
решения отсутствуют. В этой папке собраны концептуальные материалы, из которых в будущем
будет сформирован фирменный стиль: образ быка и медведя, буква **S**, объединённая с
формой инь-янь, финансовые графики, свечные паттерны, эстетика арены.

Все изображения и примеры являются **исключительно референсами и идеями направления**.
Подробное описание концепции — в `brand_identity_main_idea/readme.md`.

Все архивы **разархивированы** и лежат в подпапках по названию архива.

Материалы предоставлены **от разных людей** — каждый видел свои плюсы и минусы,
каждый по-своему презентовал идеи, и **каждый использовал разные движки**.
Некоторые ошибки и баги, описанные в архивах, могут не являться критичными.

## Секции финального релиза

Финальный продукт состоит из **6 секций**, разработанных в строгом порядке.
Каждая секция покрывается детальным ТЗ в `docs/specs/`.

| № | Секция | ТЗ (docs/specs/) | Приоритет | Статус |
|---|---|---|---|---|
| 1 | **Концепция и структура** (формула игры, 4 основных элемента, Академия/Арена) | `CONCEPT_IDEAS.md` | 🔴 Критично | 💡 Идеи |
| 2 | **Этапы освоения** (5 осей, как интерфейс обесцвечивается) | `CONCEPT_IDEAS.md` §2 | 🔴 Критично | 💡 Идеи |
| 3 | **Механики** (правила, эволюция, конфиг) | `CONCEPT_IDEAS.md` §1 | 🔴 Критично | 💡 Идеи |
| 4 | **Микро-навыки, враги, вкладки данных, цепочки** (данные для генератора заданий) | `CONCEPT_IDEAS.md` §4 | 🔴 Критично | 💡 Идеи |
| 5 | **Арт-стандарт** (как рисуются враги и стадии) | `README_DESIGN_SYSTEM.md` | 🟡 Важно | ♽ Референсы в game_characters/ |
| 6 | **Архитектура** (как собрано: клиент, сервер, аналитика) | — | 🔴 Критично | 💡 В планах |

> **Важно:** все секции находятся на стадии идей. Концептуальные материалы в
> `CONCEPT_IDEAS.md` сохранены от предыдущей реализации и служат отправочной
> точкой для переработки. Код в `phaser/src/` сброшен до фундамента.

## Эталонные источники (только для вдохновения)

Следующие внешние папки содержат эталонные документы и промпты — **никогда не
копировать код из них**. Только изучать идеи, переписывать заново на Phaser 4 + Fastify:

- signal-arena-all-prompts-v1.2/ — фазовый план (01→09) с workflow командами
- arenaui-main 3/ — ТЗ, design system, контракты (скопированы в docs/specs/)

## Протокол разработки

Разработка идёт по секциям: Foundation → Core Loop (L0–20) → Content →
UI & Assets → Motion & Audio → QA gate → Backend → Scale L21–99 → Future GameFi.

DEVGUIDE.md содержит таблицу задач со статусами, приоритетами и
жёсткими ограничениями. AI-агенты при выполнении задач **обязаны** сверяться с ним.
GameFi, токены, NFT, звук — строго после релиза и QA gate.

## Глоссарий

Сложные термины переводятся на простой язык в `docs/glossary.md`.

**Два вида терминов:**

| Тип | Что делать | Примеры |
|---|---|---|
| **Термины индустрии** | **Оставлять как есть** | FOMO, loss aversion, leverage, slippage, support/resistance |
| **Проектные термины** | **Упрощать** | атомы → навыки, свиток ошибок → журнал ошибок |

Игрок не должен ничего расшифровывать. Если термин есть во всех обучающих
материалах трейдинга — оставляем. Если это выдуманное название из ТЗ — заменяем
простым словом (атомы → навыки).

## Статус текущего кода

Код в `phaser/src/` сброшен до фундаментального уровня: конфиг игры,
BootScene, UI-примитивы и утилита rng. Тесты запущены заново по мере
реализации новых механик. Ссылки на `CONCEPT_IDEAS.md` следует сверять
с `DEVGUIDE.md` при выполнении задач.
