## 0. Архитектурные идеи (изначне концептуальные)

Это идеи, которые **должны пережить любой ресет** — они не зависят от кода,
а только от подхода к обучению.

### 0.1 Игрок осваивает материал, а не сменяет скин

**Суть:** интерфейс не просто перекрашивается между эпохами. Он **убирает костыли**:

```
Подсветка улик → Подсказка после ошибки → Нет подсказок → Ложные подсказки
```

- На старте: всё подсвечено, подсказки на картах, ярлыки на новостях.
- На L99: интерфейс может **дезинформировать** — ложные ярлыки как ловушка.

Это не смена палитры. Это **системное снятие обучающих подсказок**.
Скелет интерфейса — один: условия → источники → карты → ответ.
Меняются только токены и набор видимых элементов.

### 0.2 Принцип нераскрытия ответа

**Ни заголовок, ни цвет кнопок, ни арт врага не должны подсказывать ответ.**

Это работает на трёх уровнях:
- **UI-уровень:** цвет кнопок не кодирует right/wrong; заголовок над заданием
  не выдаёт логику; арт врага не содержит читаемых цифр или стрелок.
- **Конструктор-уровень:** каждый дистрактор (неверный ответ) привязан к
  типовой ошибке и конкретному врагу. Верный ответ имеет улику; неверные — нет.
- **Построение-уровень:** задание строится от учебной цели, а не из случайного
  набора врага + источников + ответов.

### 0.3 Лестница навыков: распознавание → применение → комбинация → перенос

Сложность растёт **не** «ещё больше кликов». Она растёт по лестнице:

| Стадия | Что тренирует | Пример |
|--------|--------------|--------|
| **Распознавание** | выявить паттерн | «это пробой без объёма» |
| **Применение** | действовать по паттерну | «не входить, ждать ретест» |
| **Комбинация** | объединить 2+ навыка | объём + FOMO-психология |
| **Перенос** | в новом контексте | тот же паттерн в деривативах |

Это совпадает с концепцией врагов + карт: используя базу врагов и карт,
можно собрать **любую** степень сложности. S1 = распознавание, S2 = применение,
S3 = комбинация (другой домен), S4 = перенос.

### 0.4 Персонализация через ошибки

**Каждая ошибка → запись → новая задача через 3–5 встреч.**

- Запись: враг + навык + пропущенная улика + статус (открыта/закрыта).
- Повтор — всегда в новой обёртке: другой актив, другая формулировка, тот же навык.
- Закрывается только верным решением с доказательством.
- maxEntries: ~12. Приоритет — повтор ошибок.

Это **спейсд повторение по личным ошибкам**, а не рандомный трек.

### 0.5 Таймер как метрика (бюджет → таймер)

**Было:** бюджет риска как лимит сессии (100 начальных, -N за ошибку, +6 за победу).

**Переработано:** таймер/лимит времени — как метрика производительности:
- Даже если все ответы верны, **кто быстрее** — тот лучше.
- Бюджет риска сохраняется как **стимул**: ошибки стоят, правильные дают бонус,
  но **не как лимит сессии** — а как фактор в оценке ответа.
- Бюджет можно **восстанавливать** за правильные решения или покупать
  в маркетплейсе (gamefi 2.0, см. §0.7).

**Free account:** строже — меньше бюджета, меньше шансов.
**Premium:** снимает некоторые ограничения, но **не даёт преимущества в самих решениях**.

### 0.6 Четырёхблочный скелет задания

Один и тот же на L0 и L99:

```
1. Условия/ситуация      (вопрос + контекст)
2. Источники данных       (вкладки: График, Новости, Позиция...)
3. Карты навыков           (выбор действия)
4. Форма ответа           (варианты / план карт / свободный ввод)
```

Сложность = **качество данных и конфликт сигналов**, не количество блоков.
Максимум 3 вкладки источников на экране — мобильный constraint.

### 0.7 GameFi 2.0: монетизация через маркетплейс

**Не внедряется сразу.** На старте фокус на:
- **Скины и косметика** в маркетплейсе (темы интерфейса, карты, трофеи).
- **Сезонные события** с эксклюзивными визуалами.

**Без:** рекламы, «купить опыт», pay-to-win. Free account проходит весь контент,
только медленнее и без косметики.

**Premium** даёт:
- Расширенную статистику и калибровку.
- Глубину свитка ошибок.
- Дополнительные режимы погоды и событий.
- Но **никогда не влияет на данные, карты, ответы или бюджет**.

## 1. Механики (кандидаты на реализацию)

Это идеи механик, реализованных ранее. Они работают, но подвергаются
пересмотру. Ниже — суть, как была реализована, и идеи для переработки.
**Никаких номеров (M1–M15). Механика = её функция, а не метка.**

### Улика

**Суть:** игрок должен найти подтверждающие данные, прежде чем давать ответ.
Ответ без улики = "угадайка" → урезанная награда.

**Как было:** свечи с интерактивными зонами, EvidenceStrip внизу, подсветка
в начале, 1–2 улики в зависимости от уровня.

**Идея для переработки:** сделать улику **стимулом к лучшей награде**,
а не обязательным валидатором. Или: убрать вовсе на ранних этапах.

### Стек решений

**Суть:** вместо одного ответа — упорядоченный план из N карт.

**Как было:** CardRail в режиме `stack`, 3–4 слота, порядок важен.

**Идея:** стек может быть не «правильный порядок», а «правильный набор».

### Ставка уверенности

**Суть:** после ответа — low/mid/high, влияет на потери/выигрыш.

**Как было:** 3 кнопки, confMul в scoring.ts.

**Идея:** добавить **калибровку** — система запоминает, насколько
игрок переоценивает себя, и подстраивается.

### Вердикт конфликта

**Суть:** выбрать A или B перед действием. Ошибочный вердикт обнуляет ответ.

**Как было:** VerdictRow с двумя колонками.

**Идея:** сделать **шкалу уверенности** вместо бинарного выбора.

### Опознание врага

**Суть:** после ответа — «кто был врагом?» из вариантов того же домена.

**Как было:** FeedbackOverlay, 2–4 портрета.

**Идея:** сделать опознание **обучающим**, а не угадайкой — показывать,
почему выбранный враг ошибается.

### Проигрыш вперёд

**Суть:** после ответа анимируется 6 свечей «что было дальше».

**Как было:** CandleChart.playForward, цвет заливки green/red.

**Идея:** включить изменение позиции — «а если бы ты пошёл — где стоп».

### Свиток ошибок

**Суть:** каждая ошибка сохраняется и возвращается через 3–5 встреч.

**Идея для переработки:** ошибка может **прогрессировать** — каждая
повторная попытка становится сложнее, а не просто перефразированной.

### Комбо карт

**Суть:** N верных ответов с нужными картами → комбо раскрывается.

**Как было запланировано (НЕ реализовано):** combos.ts с 25 комбо,
враги требуют comboRequired, но проверка не работала.

**Идея:** комбо по **качеству**, а не количеству — «5 верных ответов
с этими картами подряд» вместо «N раз использовать комбинацию».

### Слепой источник

**Суть:** за ресурс можно открыть скрытую вкладку с данными.

**Как было:** 4-я вкладка "Открыть за 6 запаса".

**Идея:** вместо платной вкладки — **неопределённый источник**,
который может оказаться ложью (ложные метки на поздних этапах).

### Холодная голова

**Суть:** пауза после серии ошибок.

**Как было:** "Выдохни. Спешка уже стоила тебе очков." + 1.4с задержка.

**Идея:** пауза должна быть **выбором**, а не принудительной:
«выйти и подождать» vs «торговать дальше в тильте».

### Мутация сценария

**Суть:** каждая встреча = шаблон + seed. Мутация: актив, таймфрейм,
зеркало, числа, формулировка, порядок ответов.

**Идея:** мутация может быть **адаптивной** — усиливать твои слабые зоны.

### Рост врага

**Суть:** 33 врага, 4 стадии. Враг растёт с игроком.

**Идея для переработки:** вместо «победить врага» —
**«исцелить» его**. Ошибка = рана, а не соперник.

### Погода рынка

**Суть:** каждый день — режим рынка (TREND/FLAT/VOLATILE/NEWS/LATE_CYCLE).

**Идея:** погода должна **влиять на сценарии** — не просто выбор задач,
а изменение распределения данных.

### Тень толпы

**Суть:** показывает, как ответили другие игроки.

**Идея:** тень может быть **динамической** — реальная статистика
от всех игроков, а не синтетическая.

### Ресурс риска

**Суть:** ограничение на ошибки. +6 за победу, -N за ошибку.

**Идея для переработки:** сделать **восстанавливаемым ресурсом**
(как MP в RPG) — тратишь на действия, восстанавливаешь за правильные решения.
Или: убрать как лимит сессии, оставить как **фактор scoring**.

## 2. Прогрессия (бывшие эпохи)

### 2.1 Пять осей взросления

Идея: один скелет интерфейса, пять осей растут по мере прогресса:

| Ось | L0–20 | L21–50 | L51–80 | L81–99 |
|-----|-------|--------|--------|--------|
| **Визуальный тон** | граффити, неон | чистые панели | плотный монохром | минимализм |
| **Костыли** | подсветка, подсказки | подсказка после ошибки | нет | ложные подсказки |
| **Данные** | ярлыки на всём | частично | сырой | сырой + ложь |
| **Форма ответа** | 4 варианта | +ставка | стек карт | свободная комбинация |
| **Язык обратной связи** | наставник | коллега | терминология | твой журнал |

### 2.2 Лестница сложности

Не "больше кликов" → а **качество ситуаций**:
- Распознавание → Применение → Комбинация → Перенос
- S1: один фактор. S2: два с одной карты. S3: второй домен. S4: новый контекст.

### 2.3 Переходы между эпохами

- **Событие**: анимация, перерисовка топ-бара, навигации, трофеев.
- **Необратимо**: костыли прошлых эпох не возвращаются.
- **Разминка всегда в текущей эпохе**.

## 3. UI паттерны (кандидаты на переработку)

### 3.1 Браузер источников

**Было:** вкладки с Графиком, Новостями, Позицией + слепой источник.

**Идеи для переработки:**
- Вместо вкладок — **карта источников** (как метро).
- Или **один экран с панорамой** — выбирай, на что смотреть.
   - Источники **скрываются постепенно** (на старте виден только график).

**Справочник:** `signal-arena-design-system.zip` → screens/arena-encounter.html
(BrowserShell с SourceTabs), `motion_interaction_catalog` → события 21–30.

### 3.2 Карта действия

**Было:** лента карт внизу. Режим `guided` — подсказка.

**Идеи:**
- Карты **на карте ситуации** — наложены там, где применимы.
- Или: **свободный выбор** без подсказок.

**Справочник:** design-system → SourceTab, CompactSkillCard, SkillTray;
motion → события 31–40.

### 3.3 Сетка ответов

**Было:** 4 варианта в 2 колонках.

**Идеи:**
- **Свободный ввод** или **шкала веробраности** («на сколько % входишь?»).
- **Непрямой выбор**: «какой фактор важнее» → автоматически выбирается ответ.

**Справочник:** design-system → AnswerOption (exactly four per encounter, equal width);
motion → события 41–50.

### 3.4 Обратная связь

**Было:** затемнение → результат → forward → identify → shadow → reward в одном слое.

**Идеи:**
- **Разнести на отдельные экраны** — не перегружать один слой.
- Или: **квик-ревью** в 1 экран без анимаций.

**Справочник:** design-system → ArenaFeedbackPanel; motion → события 51–60.

### 3.5 Меню и навигация

**Справочник:** design-system → TopBar, BottomNav, MoreMenu.

```
┌─ TopBar: [level] [XP] 💰 [⚡] ⚙️ ───────────────┐
├ Browser Widget (условия → источники)             │
│                                                   │
│ ┌── SkillTray (карты) ──────────────────────────┐ │
│ └───────────────────────────────────────────────┘ │
│ ┌── AnswerOption (A B C D) ─────────────────────┐ │
│ └───────────────────────────────────────────────┘ │
├ [Арена] [Академия] [Коллекция] [Магазин] [Ещё ⋯] │
└───────────────────────────────────────────────────┘
```

**Четыре правила:**
1. BottomNav — ровно 4 основных пункта. "Ещё" — overflow.
2. TopBar — без аватарки (только уровень, XP, монеты, бюджет, настройки).
3. Warm-up — внутри Арены, не отдельный экран.
4. Никогда не более 7 вкладок источников.

## 5. Что НЕ переносить

1. **Баланс-конфиг в числах** (balanceConfig.ts) — переосмыслить с нуля.
2. **FeedbackOverlay как один слой** — лучше разделить на экраны.
3. **7 источников** — может быть избыточно.
4. **Названия эпох** (street/cabinet/terminal/system) — использовать смысл,
   а не бренды.
5. **169 тестов на удалённый код** — писать заново под новые механики.
6. **Полный цикл: ответ → forward → identify → shadow → reward** —
   может быть слишком громоздко.

## 6. Глоссарий (концептуальный, без привязки к коду)

Эти термины используются в LEARNING_METHODOLOGY.md и CONCEPT_IDEAS.md.
Отображение в UI — через упрощённые слова (см. `docs/glossary.md`).

| Термин | Что значит |
|--------|-----------|
| **Улика** (evidence) | Данные на графике, в новостях или позиции, подтверждающие или опровергающие сигнал |
| **Карта** (SkillCard) | Один навык: C1 = рынок, C4 = риск... |
| **Атом** | Подпункт карты — узкий, измеримый навык (напр. «стоп до входа») |
| **Враг** (Enemy) | Персонификация типичной ошибки трейдера |
| **Стадия** | 4 формы врага: S1–S4, каждая сложнее |
| **Встреча** (Encounter) | Одна задача: данные + вопрос + ответы + улики |
| **Шаблон** | Конфиг встречи до мутации |
| **Сценарий** | Сгенерированные данные (свечи, новости, стакан, forward) |
| **Мутатор** | Перемешывает ответы/улики по seed |
| **Тень толпы** | Распределение ответов других игроков в % |
| **Запас риска** (riskBudget) | Ограниченный ресурс: расходуется на ошибки/стратегию, возвращается за правильные решения |
| **Комбо** | Связка карт, раскрывающаяся при совместном использовании в нужных ситуациях |
| **Погода** (weather) | Режим рынка: TREND/FLAT/VOLATILE/NEWS/LATE_CYCLE |
| **Прогресс** | Вся сохранёнка игрока (уровень, открытые карты, ошибки, враги) |
| **Этап** (level band) | L0–20 / L21–50 / L51–80 / L81–99 — как интерфейс «обесцвечивается» |
| **Структура этапа** | Что включено в UI на этом этапе: сколько источников, показывать ли подсветку, нужно ли убеждение |
