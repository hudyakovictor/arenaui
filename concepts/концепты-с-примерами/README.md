## Концепты

### Концепт_1

> "Первый вариант не значит что это в первую очередь"

**Суть:** в этом концепте дизайна можно поместить игру на всех уровнях сложности,
сохранив основной элемент — примитивный браузер, где каждая вкладка по мере
увеличения сложности будет представлять некоторые источники.

**По аналогии с реальным анализом:** при реальном анализе учитываются разные
источники в зависимости от ситуации. Комбинация источников тоже может быть
разной. Поэтому в основном элементе игры — браузере с вкладками — уже
достаточно.

**Дополнительно:** придуманы карты навыков. Они нужны, чтобы игрок оттачивал
систему мышления — понимать, что в данной ситуации будет полезно сделать
дополнительно (о чём не указывалось в браузере).

**Метод 20/80:** правильное решение примет, что будет полезно, и при этом в
задании не будет тратить время на изучение этого источника. Тренирует и не
отнимает время. Как игровой элемент — отлично дополняет игру.

**Карты навыков:** в будущем должны иметь значки, по которым быстро считывается
действие карты. Краткое название навыка + значок. Важно: иллюстрация не нужна —
элемент должен быть не на всю карту, а только в центральной части. Графика
должна быть средней: не слишком простой (иконка) и не слишком сложной
(иллюстрация).

### Концепт_2

**Суть:** почти идеальный в плане передачи стиля в тексте, но иллюстрации не
подходят. Внешний вид и цвета тоже отлично, но переборщено с эффектом краски.

**Приоритет:** "простота" — показать только необходимое, не рисовать другие
разделы, т.к. у всего остального приоритет на порядок ниже.

### Концепт_3

**Приоритет:** высший. Больше всего страниц прорисовано. Несмотря на "почти
идеально", есть 15–20% случаев, где участки нужно переделать. Учитывая количество
верных решений из такого большого количества — этот вариант заслуживает внимания.

**Почему лучше остальных:** на тот момент условий про "браузер" ещё не было.
Этот вариант оказался большим отрывом от остальных.

**Идея браузера:** когда внутри одной механики можно сделать задания разной
степени сложности — от самых простых до бесконечно сложных (как в игре 2048,
где внутри одной механики есть задания для бесконечных уровней сложности).

**Принцип:**
- В начале показывать минимум вкладок (1–2)
- Постепенно раскрывать количество вкладок параллельно с описанием, какой тип
  информации там содержится
- Игрок выучивает по иконкам на память
- В каждом задании не используются все вкладки одновременно
- Сложность растёт: мало вкладок → максимум (~7)
- Дополнительное действие (низкого приоритета) — тренирует использование навыков

**Монеты за раскрытие:** некоторые элементы можно раскрывать за условные монетки,
накапливаемые по мере игры. Если есть уверенность в полезности данных —
пользователи будут использовать. Можно допустить покупку данных за депозит,
но это не даст преимущества — разница в том, что основное задание решают лучше.

## Идеи по отдельности

### Топ 1 — Иллюстрации (высший приоритет)

Показан стиль иллюстраций, который виден в игре. Подходит идеально. Независимо
от выбранного концепта, иллюстрации должны быть в этом стиле.

### Топ 2 — Внешний вид карт навыков

Особенно отмечен вариант с идеальным балансом: что-то среднее между обычной
иконкой и иллюстрацией. Примеры слабо подходят, но общая идея понятна: в картах
должен быть объект или несколько объектов, по которым быстро считывается навык.
Размер карт маленький — сложные иллюстрации не считываются по миниатюрам.

### Топ 3 — Фоновые элементы (низший приоритет)

Разные элементы, которые можно разбавлять фон: хаотичные тексты (надписи на
стенах и т.п.) в тему, но не для применения. Дополнительно — 3 концепта с
общими идеями дизайн-системы. Можно брать идеи оттуда, когда нужно показать
что-то новое.

## Общая информация о игре

### Миссия

Создать игру, которая по функционалу станет лидером в этой области — не будет
никого подобного среди текущих аналогов и похожих проектов в сфере.

### Монетизация

- **Внутренний маркетплейс** — основной будущий источник прибыли
- **GameFi 2.0:** токен, блокчейн, NFT — только после того, как внутренняя
  экономика будет построена правильно
- **Премиум не даёт преимуществ:** игрок, который не раскрывал информацию, но
  решил лучше — всегда имеет преимущество. Деньги не дают преимущества при
  правильном балансе

### Экономика

- Бесплатный аккаунт + много неправильных ответов → стимулируется целевая аудитория
- При правильных ответах добавляется столько, чтобы хватило ещё на игру +
  остаётся с запасом
- Темы открываются по порядку: сначала теория в Академии → потом практика
- Через некоторое время тема считается закрытой и уходит из практики
- При закрытии главы — значительное количество монет + появляется сущность,
  которую игрок научился выявлять
- Враги появляются по уровню сложности. Игрок может догадаться кто это,
  но об этом не пишется явно — чтобы не давать преимущество тем, кто не готов

### Исследование

1. **Топ 50 источников** — чтобы знать, как должна выглядеть игра, оцененная
   на 95/100 по 120 факторам
2. **Топ 15 бирж** с учебными материалами для новичков — изучить интерфейс и
   функционал, найти общее среднее обучение типичного брокера
3. **Современные курсы (сентябрь 2026)** — выяснить все темы, составить
   партнёрский/курсчат, чтобы теория была в 2 раза полезнее существующей
4. **Стиль текста** — писать теорию в том же стиле, что и игра (панк-таблоидная
   криптосатира)

### Методология

- Делать промежуточные версии для восстановления данных в случае потери
- На старте: собрать план всех страниц при 100% готовности
- В первую версию: минимальные данные
- Фокус на дизайне и верстке всех страниц, а не на контенте
- Контент можно добавить позже
